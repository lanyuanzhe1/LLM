## 一、文档目的

本文档定义面向课程学习场景的网页端 AI Agent MVP，包括产品目标、范围边界、信息架构、页面规格、Agent 过程展示、关键交互、异常状态、数据与事件要求、验收指标以及与 Open WebUI 方案的关系。

本文档服务于三类协作者：

- 产品与教学设计人员：确认 MVP 是否构成完整的学习闭环；
- UI/UX 与前端开发人员：据此设计页面、组件和交互状态；
- 后端与 Agent 工作流开发人员：据此补齐课程上下文、会话、引用、工具状态和学习结果协议。

本文档只定义产品与交互方案，不展开具体前端框架选型、组件代码和开发排期。待本方案确认后，再单独形成实施计划。

## 二、什么是本项目的 MVP

MVP 是 Minimum Viable Product，即“最小可行产品”。它不是功能残缺的演示页面，而是用最少的页面和能力，让真实用户完成一次有价值、可重复的核心任务，并验证产品方向是否成立。

本项目的 MVP 要验证的核心假设是：

> 当 AI 能够在明确的课程上下文中检索指定资料、展示可理解的行动过程、提供带引用的讲解，并通过练习检查理解时，学生会比使用普通聊天机器人更容易获得可信、连续且可验证的学习体验。

因此，MVP 必须打通以下最小学习闭环：

```text
选择课程
  → 提出学习问题
  → Agent 检索课程资料或请求补充信息
  → 展示简洁的工具调用过程
  → 交付带引用的讲解
  → 生成理解检查或练习
  → 给出反馈并保存学习结果
  → 继续追问或进入下一知识点
```

如果只实现“输入问题—输出文本”，即使回答接入了 RAG，也只能算课程知识库聊天原型，不能算课程学习 Agent MVP。

## 三、产品定位与目标用户

### 3.1 一句话定位

> 一个围绕具体课程运行、能够检索课程资料、调用学习工具、解释行动过程、交付可追溯答案并检查学习效果的网页端对话式 Agent。

### 3.2 产品边界

本产品是运行在受控云端环境中的学习 Agent，不是本地电脑操作型 Agent。

它可以：

- 检索课程知识库、教材、课件、论文和法规；
- 根据课程资料完成答疑、讲解、总结和对比；
- 生成学习计划、复习提纲、案例分析和练习；
- 检查练习答案并分析错因；
- 保存会话、学习产物和有证据的学习结果；
- 在必要时调用受控网络检索，但必须标明课程资料与外部资料的边界。

它不可以：

- 操作用户本地电脑；
- 未经确认修改或删除课程资料；
- 将没有资料依据的内容伪装成课程结论；
- 仅根据聊天次数推断用户已经掌握知识；
- 代替教师、行业专家或用户作出高风险专业决策；
- 在学生端暴露 API 密钥、向量模型、切块参数或工作流节点等技术细节。

### 3.3 MVP 主用户

MVP 首先服务粮食储藏相关课程的学生用户。

学生的高频任务包括：

- 听不懂一个概念，希望换一种方式讲解；
- 根据指定教材或课件查找答案；
- 对比多个资料中的观点、条件和结论；
- 为考试制定复习计划；
- 根据当前章节生成练习；
- 分析错题，确定还没有掌握的知识点；
- 将一次有价值的对话保存为复习笔记。

教师、研究者和技术人员继续作为后端角色保留，但 MVP 不为每种角色开发独立的完整工作台。角色主要影响提示词、检索范围、回答结构和安全边界。教师专属后台进入后续版本。

## 四、MVP 成功标准

### 4.1 产品成功标准

MVP 上线试用后，需要回答以下问题：

1. 学生能否快速理解产品能做什么、不能做什么；
2. 学生能否在不理解工具技术细节的情况下看懂 Agent 当前在做什么；
3. 基于课程资料且带引用的回答是否比普通聊天回答更可信、更有用；
4. 学生是否愿意在回答后继续追问、查看原文或完成练习；
5. 一轮学习后，系统能否留下可复用的笔记、错题或学习结果；
6. 当资料不足或工具失败时，系统能否给出明确的下一步，而不是无响应或编造答案。

### 4.2 建议量化指标

| 指标 | MVP 目标 | 说明 |
|---|---:|---|
| 首次有效回答时间 | 用户进入课程后 3 分钟内 | 包括理解入口、提问和收到第一条有效回答 |
| 回答成功率 | ≥ 90% | 排除用户主动取消和明确越界请求 |
| 关键结论引用覆盖率 | ≥ 85% | 与现有产品方案中的 MVP 门槛一致 |
| 引用准确率 | ≥ 90% | 引用原文能够支持对应结论 |
| 引用打开率 | 观察指标 | 判断用户是否使用来源核验能力 |
| 回答后继续行为率 | ≥ 40% | 继续追问、查看来源、生成练习或保存产物之一 |
| 练习完成率 | ≥ 50% | 已启动理解检查或练习的用户中完成比例 |
| 工具状态理解率 | 可用性测试 ≥ 80% | 用户能够说清 Agent 是在检索、生成、等待还是失败 |
| 无依据时的安全兜底率 | 100% | 不得将无证据内容作为课程事实直接输出 |

### 4.3 不作为成功指标的内容

以下数据可以记录，但不能直接视为学习效果：

- 用户发送的消息数量；
- 单次会话时长；
- 阅读过多少条 AI 回答；
- Agent 调用了多少个工具；
- 生成了多少字；
- 登录或签到天数。

学习进度必须尽量来自练习表现、错因变化、理解检查和用户明确反馈。

## 五、MVP 范围

### 5.1 MVP 页面

MVP 由三个主要页面组成：

1. 我的课程；
2. 课程学习工作台；
3. 课程资料与原文查看器。

练习、轻量进度和学习产物首先嵌入课程学习工作台，不独立建设复杂页面。

### 5.2 MVP 必须具备的能力

- 课程级上下文隔离；
- 新建、保存、恢复课程内会话；
- 课程资料检索；
- 流式回答；
- Agent 行动与工具调用状态；
- 补充信息请求；
- 可点击引用和原文定位；
- 检索不足与无证据兜底；
- 停止、重试和继续追问；
- 生成少量练习并检查答案；
- 保存学习笔记、总结或学习计划；
- 保存本轮错题和有证据的学习结果；
- 桌面端可用，并具备基本响应式移动端布局；
- 空状态、加载状态、失败状态和权限状态。

### 5.3 明确不进入 MVP 的能力

- 多模型对比和复杂模型参数；
- Agent、插件或提示词市场；
- 多 Agent 协作；
- 通用工作流搭建器；
- 自动操作本地电脑或外部业务系统；
- 完整教师班级管理后台；
- 多人实时协作编辑；
- 复杂知识图谱；
- 完整的长期记忆系统；
- 精细化掌握度算法；
- 排行榜、虚拟货币和重度游戏化；
- 通用网页、应用、表格和演示稿生成器；
- 复杂的社会化分享与公开社区。

## 六、核心概念与信息架构

### 6.1 核心对象

| 对象 | 定义 | MVP 中的作用 |
|---|---|---|
| 课程 Course | 学习上下文的最高边界 | 聚合资料、章节、会话、产物、练习和进度 |
| 章节 Chapter | 课程内的内容组织单元 | 缩小检索范围，组织历史和学习目标 |
| 会话 Session | 围绕一个学习目标展开的连续对话 | 保存上下文、工具活动和回答 |
| 资料 Source | 教材、课件、论文、法规等知识来源 | 被检索、引用和原文查看 |
| 证据 Evidence | 从资料中检索出的可定位片段 | 支撑回答结论和引用 |
| 学习任务 Learning Task | 用户希望完成的具体目标 | 如概念理解、总结、计划或练习 |
| 学习产物 Artifact | 可独立保存和复用的结果 | 笔记、提纲、学习计划、案例分析 |
| 练习 Practice | 用于检查理解的题目集合 | 提供作答、反馈和错因证据 |
| 学习记录 Learning Record | 一次可验证的学习结果 | 记录练习结果、薄弱点和待复习项 |

### 6.2 信息架构

```text
全局
├── 我的课程
│   ├── 最近学习
│   ├── 待复习
│   └── 课程列表
├── 全局搜索
│   ├── 历史会话
│   ├── 学习产物
│   └── 课程资料
└── 个人设置
    ├── 学习偏好
    ├── 默认讲解难度
    └── 数据与隐私

课程
├── 学习对话
│   ├── 新建学习任务
│   ├── 按章节组织的历史会话
│   └── Agent 过程与结果
├── 课程资料
│   ├── 资料列表
│   ├── 处理状态
│   └── 原文查看器
├── 学习产物
│   ├── 笔记
│   ├── 总结
│   ├── 学习计划
│   └── 案例分析
├── 练习与错题
│   ├── 本轮练习
│   └── 待复习错题
└── 轻量进度
    ├── 已完成理解检查
    ├── 练习正确率
    └── 当前薄弱点
```

### 6.3 路由建议

| 路由 | 页面 | MVP |
|---|---|---|
| `/courses` | 我的课程 | 必须 |
| `/courses/:courseId/learn` | 新建课程学习会话 | 必须 |
| `/courses/:courseId/learn/:sessionId` | 恢复指定会话 | 必须 |
| `/courses/:courseId/resources` | 课程资料列表 | 必须 |
| `/courses/:courseId/resources/:sourceId` | 原文查看器 | 必须 |
| `/search` | 全局搜索 | 可后置到 MVP 后半阶段 |
| `/courses/:courseId/practice` | 独立练习中心 | 后续版本 |
| `/courses/:courseId/progress` | 独立学习进度页 | 后续版本 |
| `/teacher/courses/:courseId` | 教师工作台 | 后续版本 |

## 七、页面一：我的课程

### 7.1 页面目标

帮助用户快速进入一门课程或恢复最近一次学习，不承担复杂课程管理和推荐任务。

### 7.2 页面结构

```text
┌─────────────────────────────────────────────────────────────┐
│ 产品名称                         搜索      个人设置          │
├─────────────────────────────────────────────────────────────┤
│ 继续学习                                                   │
│ ┌─────────────────────────────────────────────────────────┐ │
│ │ 粮油储藏学 A · 第三章                                   │ │
│ │ 上次：低温储粮如何控制温度和水分                        │ │
│ │ 1 个待复习知识点                         [继续学习]      │ │
│ └─────────────────────────────────────────────────────────┘ │
│                                                             │
│ 我的课程                                      [创建课程]    │
│ ┌──────────────┐ ┌──────────────┐ ┌──────────────┐          │
│ │ 粮油储藏学 A │ │ 储粮昆虫学   │ │ 粮油检验基础 │          │
│ │ 12 份资料    │ │ 5 份资料     │ │ 8 份资料     │          │
│ │ 最近 2 小时前│ │ 最近 3 天前  │ │ 尚未开始     │          │
│ └──────────────┘ └──────────────┘ └──────────────┘          │
└─────────────────────────────────────────────────────────────┘
```

### 7.3 课程卡片字段

- 课程名称；
- 课程封面色或简单图标；
- 资料数量及资料处理异常提示；
- 最近学习章节；
- 最近会话标题；
- 待复习数量；
- 最近访问时间；
- 继续学习按钮。

### 7.4 主要操作

- 进入课程；
- 继续最近会话；
- 创建课程；
- 搜索已有课程；
- 进入课程资料管理。

### 7.5 页面状态

#### 首次使用

显示产品能力说明和一个主要按钮：

> 创建一门课程，上传教材或课件，然后开始基于课程资料学习。

#### 有课程但尚无会话

课程卡片显示“开始第一次学习”，不显示虚假的进度。

#### 资料处理异常

课程卡片显示非阻塞提示，例如“1 份资料解析失败”，用户仍可进入课程。

#### 加载失败

保留课程页面框架，显示重试按钮，不清空用户已看到的其他课程。

## 八、页面二：课程学习工作台

### 8.1 页面目标

课程学习工作台是 MVP 的核心页面，承担提问、Agent 运行、来源核验、产物查看、练习和继续学习。

### 8.2 桌面端整体布局

```text
┌────────────────────────────────────────────────────────────────────────────┐
│ 粮油储藏学 A / 第三章   目标：掌握低温储粮   本轮资料：课程资料 12 份     │
├───────────────┬────────────────────────────────┬───────────────────────────┤
│ 课程与会话     │ 学习对话                       │ 上下文工作区               │
│               │                                │                           │
│ [新建学习任务] │ 用户问题                       │ [来源] [产物] [进度]       │
│               │                                │                           │
│ 第三章         │ Agent 行动                     │ 引用原文                   │
│ · 低温储粮答疑 │ ● 正在检索第三章资料            │ 文件、页码、证据片段       │
│ · 考前复习计划 │ ✓ 已找到 8 个相关段落           │                           │
│               │ ○ 正在检查引用                  │ 学习笔记预览               │
│ 第二章         │                                │                           │
│ · 害虫防治总结 │ 回答正文 [1][2]                 │ 本轮练习结果               │
│               │                                │                           │
│ 课程资料       │ [换个例子] [生成3题] [保存笔记] │                           │
│ 练习与错题     │                                │                           │
│               │ ┌────────────────────────────┐ │                           │
│               │ │ 输入问题、粘贴内容或上传…  │ │                           │
│               │ └────────────────────────────┘ │                           │
└───────────────┴────────────────────────────────┴───────────────────────────┘
```

建议桌面端宽度：

- 左侧课程与会话栏：240–280px；
- 中央对话区：最小 560px，优先占据剩余空间；
- 右侧上下文工作区：340–420px；
- 页面总宽度不足时，先收起左栏，再将右栏切换为抽屉。

### 8.3 顶部课程上下文栏

课程上下文栏始终可见，展示：

- 当前课程；
- 当前章节或“全课程”；
- 当前学习目标；
- 本轮资料范围；
- 用户角色；
- 讲解难度。

示例：

```text
粮油储藏学 A / 第三章 / 理解模式 / 大学本科 / 仅课程资料
```

用户可以修改章节、学习目标和资料范围，但修改时必须说明其影响。例如：

> 切换为“全课程”后，后续问题可能引用其他章节的资料。

### 8.4 左侧课程与会话栏

左栏包含：

- 新建学习任务；
- 课程章节；
- 按章节分组的历史会话；
- 课程资料入口；
- 练习与错题入口；
- 会话搜索。

会话条目展示：

- 自动生成或用户编辑的标题；
- 最近更新时间；
- 未完成或等待输入状态；
- 当前仍在生成时的运行指示；
- 是否产生学习产物或练习。

历史会话优先属于课程和章节，不把所有聊天平铺到全局列表。

### 8.5 中央聊天区

中央区域支持以下消息类型：

| 消息类型 | 作用 |
|---|---|
| 用户消息 | 学习问题、补充信息、练习作答 |
| Agent 文本回答 | 直接结论、讲解、例子和建议 |
| 任务计划 | 复杂任务的可编辑短计划 |
| 工具活动卡 | 检索、比较、生成、校验等行动状态 |
| 输入请求卡 | 请求补充章节、目标、案例条件等必要信息 |
| 引用块 | 连接回答结论与证据 |
| 学习产物卡 | 保存笔记、总结、计划或案例分析 |
| 练习卡 | 题目、作答、评分、解析和错因 |
| 错误恢复卡 | 失败原因、已完成内容和下一步操作 |

### 8.6 输入区

输入区由三层组成。

#### 第一层：当前上下文标签

```text
[粮油储藏学 A] [第三章] [仅课程资料] [讲解模式]
```

用户可以删除或修改标签，系统不得隐藏实际生效的上下文。

#### 第二层：多行输入框

支持：

- 输入普通问题；
- 粘贴一段材料；
- 上传临时文件或图片；
- 使用快捷键发送；
- Agent 运行时继续编辑下一条消息。

#### 第三层：学习动作

保留少量高频入口：

- 帮我理解；
- 总结本章；
- 制定计划；
- 用例题教我；
- 检测掌握程度。

不在输入区展示模型选择、温度、Top P、向量检索参数或工具函数名。

### 8.7 右侧上下文工作区

右侧只保留三个一级标签。

#### 来源

- 当前回答引用的资料；
- 文件名、资料类型、页码或章节；
- 证据原文；
- 引用支持的回答句子；
- 打开完整原文；
- 报告“引用不支持结论”。

点击回答中的引用编号时，右侧自动切换到来源标签并定位对应证据。

#### 产物

MVP 支持四种产物：

- 学习笔记；
- 章节总结或复习提纲；
- 学习计划；
- 案例分析。

产物独立于聊天保存，支持：

- 查看；
- 重命名；
- 局部修改；
- 复制；
- 下载 Markdown 或文本；
- 回到产生该产物的会话。

#### 进度

MVP 只展示轻量且有证据的结果：

- 本轮练习数量与正确率；
- 用户自评“已理解/仍不理解”；
- 本轮发现的薄弱点；
- 待复习错题；
- 建议的下一步。

不在 MVP 中生成复杂百分制掌握度或漂亮但缺乏依据的知识图谱。

### 8.8 移动端布局

- 顶部保留课程名称和上下文摘要；
- 左栏变为课程导航抽屉；
- 中央聊天区占满宽度；
- 右侧来源、产物和进度变为底部全屏面板；
- 工具活动卡默认折叠；
- 输入区固定在底部，但必须避开系统键盘和安全区域；
- 引用点击后打开原文面板，关闭后回到原回答位置。

## 九、页面三：课程资料与原文查看器

### 9.1 页面目标

让用户理解课程 Agent 可以使用哪些资料、资料是否可用，以及回答引用的原文在哪里。

### 9.2 资料列表

资料列表字段：

- 文件名；
- 资料类型：教材、课件、论文、法规、教师资料、其他；
- 所属课程和章节；
- 权威等级；
- 文件大小；
- 解析或 OCR 状态；
- 知识块数量；
- 最近更新时间；
- 是否允许学生检索；
- 操作菜单。

示例：

```text
粮油储藏学A.pdf          教材   已完成      356 个知识块
第三章课程课件.pptx       课件   已完成       42 个知识块
河南省相关条例.pdf        法规   OCR 处理中    暂不可检索
课堂笔记.docx             讲义   解析失败      [查看原因] [重试]
```

### 9.3 资料处理状态

统一状态：

- 等待上传；
- 上传中；
- 待处理；
- 解析中；
- OCR 处理中；
- 向量化中；
- 已完成；
- 部分可用；
- 失败；
- 已停用。

“部分可用”用于存在少量无法解析页面、表格或图片，但已有部分内容可检索的情况。用户必须能查看限制说明。

### 9.4 原文查看器

原文查看器采用双栏：

- 左侧：PDF、PPT 或文本原文；
- 右侧：资料信息、章节结构、当前证据片段和相关引用。

从回答点击引用进入时，查看器必须：

1. 打开正确资料；
2. 定位到页码、章节或文本区间；
3. 高亮对应证据；
4. 显示该证据支持回答中的哪一句话；
5. 提供返回原会话的入口。

如果当前元数据无法精确到页码，必须显示“当前只能定位到文档片段”，不能伪造页码。

### 9.5 权限

学生默认可以：

- 查看允许访问的资料；
- 搜索资料；
- 打开引用原文；
- 上传仅用于当前会话的临时资料。

学生默认不可以：

- 删除课程公共资料；
- 修改资料权威等级；
- 修改解析、切块和检索参数；
- 将临时资料发布为课程公共资料。

资料管理和重新处理属于教师或管理员权限。

## 十、核心交互流程

### 10.1 流程一：课程资料问答

```text
用户进入课程
  → 选择第三章
  → 提问“低温储粮为什么可以抑制害虫？”
  → 系统继承课程、章节、角色和资料范围
  → Agent 检索第三章课程资料
  → UI 展示检索与引用校验状态
  → Agent 生成分步讲解和引用
  → 用户点击引用查看原文
  → 用户选择“换个例子”或“检测我的理解”
```

回答建议结构：

1. 一至三句话直接结论；
2. 分步解释；
3. 示例或适用条件；
4. 可点击引用；
5. 一个后续学习动作。

### 10.2 流程二：信息不足

用户请求依赖必要信息时，Agent 不得猜测。

例如案例分析缺少粮种、水分或粮温趋势时：

```text
Agent 识别缺失字段
  → 展示输入请求卡
  → 用户填写或选择
  → 原任务从中断位置继续
```

输入请求卡只询问当前任务真正需要的信息，避免一次要求用户填写大量表单。

### 10.3 流程三：复杂任务

对于“根据第三章和两篇论文制定七天复习计划”一类任务：

1. Agent 生成三至五步短计划；
2. 用户可以修改资料范围、时间和输出形式；
3. 用户确认后开始；
4. UI 展示当前步骤、已完成步骤和取消按钮；
5. 结果作为独立学习计划产物打开；
6. 用户可继续要求局部调整。

普通单轮问答不展示任务计划，避免人为制造复杂感。

### 10.4 流程四：练习与反馈

```text
用户点击“生成3题”
  → Agent 默认使用当前知识点和本轮资料
  → 用户选择题量与难度，或直接使用默认值
  → 系统逐题展示
  → 用户作答
  → 系统给出正确性、解析、引用和错因
  → 保存错题与本轮学习记录
  → 推荐继续讲解或相似题
```

练习模式：

- 选择题；
- 判断题；
- 简答题；
- 案例题。

MVP 默认一次一至五题。长试卷生成和正式考试模式不进入 MVP。

### 10.5 流程五：保存学习产物

用户可以将回答转为：

- 学习笔记；
- 复习提纲；
- 学习计划；
- 案例分析。

产物创建后：

1. 右侧产物标签自动打开；
2. 显示产物标题、来源范围和生成时间；
3. 用户可以编辑或继续用对话修改；
4. 产物保留来源引用；
5. 产物记录原始会话链接。

## 十一、Agent 过程与工具调用状态设计

### 11.1 设计目标

用户需要知道 Agent 当前在做什么、使用了什么资料、是否需要等待、是否遇到问题，以及自己能否干预。

系统展示“行动摘要”，不展示模型内部思维链，也不展示工具原始 JSON。

### 11.2 Agent 运行状态

| 状态 | 用户理解 | UI 表现 |
|---|---|---|
| ready | 可以开始 | 正常输入区 |
| planning | 正在规划复杂任务 | 简短计划卡 |
| running | 正在执行 | 当前行动、进度、停止按钮 |
| needs_input | 需要用户补充信息 | 输入请求卡、会话等待标记 |
| completed | 已完成 | 回答、来源、产物或练习 |
| failed | 无法继续 | 错误说明、已完成内容、重试或替代方案 |
| cancelled | 用户已停止 | 保留已有内容，可重新开始 |

### 11.3 工具调用状态

工具状态统一为：

```text
排队中 → 运行中 → 已完成
                  ├→ 需要输入
                  ├→ 失败
                  └→ 已取消
```

工具卡展示：

- 用户可理解的动作名称；
- 当前状态；
- 作用对象；
- 找到的结果数量；
- 运行时长；
- 展开后的来源和结果摘要；
- 失败后的恢复动作。

示例：

```text
✓ 检索第三章课程资料
  找到 8 个相关段落，来自 3 份资料，用时 1.8 秒
```

而不是：

```text
retrieve(top_k=8, project_id="xxx") success
```

### 11.4 建议的用户语言

| 后端能力 | UI 文案 |
|---|---|
| retrieve | 正在检索课程资料 |
| generate | 正在组织讲解 |
| case_evaluate | 正在分析案例条件 |
| citation_validate | 正在检查回答引用 |
| web_search | 正在检索公开资料 |
| practice_generate | 正在生成练习 |
| practice_evaluate | 正在检查你的答案 |
| artifact_create | 正在创建学习笔记 |

### 11.5 何时展示详细过程

- 预计小于 3 秒的普通问答：只显示一行即时状态；
- 预计 3–8 秒：显示当前行动；
- 超过 8 秒或包含多个步骤：显示任务计划和已完成步骤；
- 需要用户输入：保持会话在等待状态，并在历史列表中标记；
- 失败：保留成功完成的步骤和已获得的来源。

### 11.6 用户控制

运行过程中允许：

- 停止；
- 修改资料范围；
- 追加说明并排队；
- 取消等待中的后续消息；
- 工具失败后重试；
- 切换为只使用当前已有资料；
- 在允许的情况下改用公开检索。

只读工具可以自动运行。涉及共享、发布、覆盖记录或修改课程公共资料的操作必须确认。

## 十二、引用与可信度设计

### 12.1 引用要求

每个关键事实性结论应包含一个或多个引用。引用对象至少包含：

- `evidence_id`；
- `source_id`；
- 来源名称；
- 资料类型；
- 页码、章节或文本位置；
- 证据片段；
- 来源权威等级；
- 对应回答句子。

### 12.2 回答中的引用

回答中使用紧邻结论的编号引用：

```text
低温会降低储粮害虫的代谢和繁殖活动，但具体效果受到虫种和温度范围影响。[1][2]
```

鼠标悬停或点击时：

- 显示来源名称；
- 显示一小段原文；
- 提供“在原文中查看”；
- 提供“引用不支持该结论”的反馈。

### 12.3 资料不足

当检索质量不足时，不能正常生成确定性课程结论。建议展示：

> 当前课程资料中没有找到足够依据。你可以上传相关资料、扩大到全课程范围，或允许我明确标注后使用公开资料进行解释。

如果用户允许使用通用知识或公开资料，回答必须区分：

- 来自课程资料；
- 来自公开资料；
- 模型的一般性解释。

## 十三、学习产物设计

### 13.1 产物与聊天回答的区别

聊天回答用于即时交流，学习产物用于长期保存、编辑、复习和导出。

满足以下条件的内容应建议保存为产物：

- 结构完整且可独立阅读；
- 用户之后可能复习或修改；
- 包含多个章节或多份资料的综合结果；
- 学习计划、复习提纲或案例报告；
- 用户明确要求保存。

### 13.2 产物字段

- 标题；
- 类型；
- 所属课程和章节；
- 正文；
- 引用列表；
- 创建时间与更新时间；
- 来源会话；
- 生成时使用的资料范围；
- 版本号。

MVP 可以只保留最近版本和上一个版本。完整版本树进入后续版本。

## 十四、练习与学习进度

### 14.1 练习生成原则

- 默认围绕当前课程、章节和知识点；
- 优先使用课程资料；
- 题目、答案和解析应能追溯来源；
- 难度与用户当前水平匹配；
- 一次题量保持较小；
- 不在题目展示前泄露答案；
- 简答题评价应说明关键得分点，不只给出对错。

### 14.2 错因分类

MVP 使用少量稳定分类：

- 概念混淆；
- 适用条件遗漏；
- 因果关系理解错误；
- 关键步骤遗漏；
- 资料记忆错误；
- 表达不完整；
- 题意理解错误。

### 14.3 进度更新规则

只有发生以下行为时才更新学习记录：

- 用户完成一道或一组练习；
- 用户完成 Agent 提出的理解检查；
- 用户明确标记“已理解”或“仍不理解”；
- 用户在后续相似题中表现发生变化；
- 教师确认学习结果。

阅读回答、打开资料和聊天时长可以作为行为记录，但不直接提高掌握度。

### 14.4 MVP 轻量进度展示

```text
本轮学习
✓ 完成 3 道练习
✓ 2 道正确
△ 薄弱点：低温条件下的水分控制
→ 建议：复习教材第 45–48 页后完成 1 道相似题
```

## 十五、异常与恢复设计

| 异常 | UI 应对 |
|---|---|
| 课程没有资料 | 解释可用能力，提供上传资料或使用底座库入口 |
| 资料仍在处理 | 显示进度，可先使用已完成资料 |
| 检索无结果 | 提供扩大章节范围、上传资料或允许公开检索 |
| 检索质量不足 | 不输出确定性结论，明确说明证据不足 |
| 引用验证失败 | 标记未支持内容，重生成或删除对应结论 |
| Agent 需要信息 | 展示结构化输入请求卡 |
| 工具超时 | 保留已完成步骤，支持重试或跳过 |
| 流式连接断开 | 尝试恢复；失败时保留已接收内容并提供继续生成 |
| 生成练习失败 | 保留当前回答，允许重新生成或调整题型 |
| 文件解析失败 | 显示原因和重试入口，不影响其他资料 |
| 用户停止任务 | 保留已有来源和草稿，不记为完成 |
| 权限不足 | 解释当前权限和可联系的角色，不显示无效按钮 |

错误文案必须包含：

1. 发生了什么；
2. 哪些内容已经保留；
3. 用户现在可以做什么。

避免只显示“请求失败”“500”或原始异常堆栈。

## 十六、与现有后端的映射

### 16.1 已具备能力

当前 `app/` 已具备以下可复用基础：

| 现有字段或能力 | MVP 映射 |
|---|---|
| `project_id` | MVP 阶段直接映射为课程或课程知识域标识 |
| `session_id` | 课程内会话标识 |
| `user_id` | 用户和学习记录归属 |
| `role` | 学生、教师、研究者、技术人员角色 |
| `RetrieveRequest` | 课程资料检索 |
| `RetrievalQuality.sufficient` | 判断资料是否足以回答 |
| `GenerateRequest` | 基于证据的回答生成 |
| `CaseEvaluateRequest` | 储粮案例条件分析 |
| `CitationValidateRequest` | 回答引用校验 |
| `Evidence` | 来源与证据卡片基础对象 |
| SSE 流式响应 | 流式文本和过程事件传输基础 |

### 16.2 需要补齐的业务对象

正式 MVP 需要在现有 API 之上补齐：

- Course；
- Chapter；
- Session 元数据；
- Source 处理与权限状态；
- Artifact；
- Practice、Question、Attempt；
- LearningRecord；
- 用户学习偏好；
- Agent Activity。

### 16.3 事件协议建议

当前事件主要覆盖工作流帧、错误和完成。为了支持正式 Agent 前端，建议增加语义事件：

| 事件 | 作用 |
|---|---|
| `plan_created` | 创建复杂任务计划 |
| `plan_updated` | 更新步骤状态 |
| `tool_started` | 工具开始执行 |
| `tool_progress` | 工具过程更新 |
| `tool_completed` | 工具完成及结果摘要 |
| `tool_failed` | 工具失败及可恢复动作 |
| `input_required` | 请求用户补充必要信息 |
| `citation_added` | 增加可点击引用 |
| `artifact_created` | 创建学习产物 |
| `practice_created` | 创建练习 |
| `learning_record_updated` | 更新有证据的学习结果 |
| `message_delta` | 流式回答文本 |
| `done` | 本轮任务结束 |

建议统一事件信封：

```json
{
  "event_id": "evt_xxx",
  "request_id": "req_xxx",
  "session_id": "session_xxx",
  "course_id": "course_xxx",
  "type": "tool_progress",
  "timestamp": "2026-07-29T10:00:00+08:00",
  "data": {}
}
```

前端只能依赖稳定的事件类型和字段，不能解析模型自由文本来猜测工具状态。

## 十七、Open WebUI 与正式 MVP 的关系

### 17.1 Open WebUI 适合承担的角色

Open WebUI 适合作为 Phase 0 快速联调和内部演示壳，用于验证：

- 用户登录；
- 会话历史；
- OpenAI 兼容 API；
- 流式回答；
- 基础文件上传；
- 知识库问答；
- Markdown 渲染；
- 基础工具调用。

它可以帮助团队尽快验证后端 RAG 和 Agent 链路，不应被否定或废弃。

### 17.2 Open WebUI 不适合作为正式课程 MVP 最终界面的原因

- 其一级对象是模型和聊天，而不是课程；
- 课程、章节、学习目标和资料范围无法始终以产品化方式展示；
- 引用跳转、证据原文和回答句子之间的映射定制有限；
- 学习产物、练习、错题和轻量进度不是原生核心对象；
- 通用模型、参数、工具和工作区入口会增加学生认知负担；
- 只使用 OpenAI Chat Completion 文本流会损失结构化工具状态和学习事件。

### 17.3 推荐演进路线

```text
Phase 0：Open WebUI + OpenAI 兼容端点
  用于后端联调、内部体验和快速展示

Phase 1：自研课程学习工作台
  对接现有业务 API 与语义 SSE 事件

Phase 2：保留 OpenAI 兼容端点
  继续支持 Open WebUI、第三方 SDK 和调试工具
```

OpenAI 兼容端点不是浪费：它继续作为通用兼容层；正式前端则使用能够表达课程、来源、工具、产物和学习结果的业务协议。

## 十八、非功能要求

### 18.1 性能

- 普通操作应在 100ms 内产生视觉反馈；
- 提问后 1 秒内显示 Agent 已接收并开始处理；
- 流式回答首个有效内容目标小于 3 秒；
- 长任务持续显示状态，不能让界面静默等待；
- 课程和会话列表支持增量加载；
- 大型 PDF 原文查看采用按页或按需加载。

### 18.2 可访问性

- 所有主要操作支持键盘访问；
- 动态状态使用适当的 `aria-live`；
- 状态不能只依赖颜色表达；
- 保持可见焦点；
- 支持减少动态效果；
- 正文和引用满足基本对比度要求；
- 工具运行状态应能被屏幕阅读器理解。

### 18.3 安全与隐私

- 前端不保存服务端密钥；
- 课程资料访问必须经过后端权限校验；
- 临时上传资料与课程公共资料明确区分；
- 会话、资料、引用和学习记录按用户与课程隔离；
- 删除课程或会话前说明影响并二次确认；
- 记录高风险工具操作和权限变化；
- AI 生成内容明确标识；
- 专业风险回答保留适用条件和人工确认提示。

### 18.4 可观测性

至少记录：

- 请求 ID、会话 ID、课程 ID 和用户角色；
- 任务类型；
- 工具开始、完成、失败和耗时；
- 检索候选与最终引用；
- 引用校验结果；
- 首字延迟与总响应时间；
- 用户停止、重试和反馈；
- 练习生成与完成情况；
- 学习产物创建情况。

## 十九、MVP 验收用例

### 19.1 主流程验收

1. 用户能够创建或进入一门课程；
2. 用户能够在课程内选择章节并提问；
3. Agent 能够检索该课程资料；
4. UI 能够展示检索、生成和引用校验状态；
5. 回答能够流式展示；
6. 回答中的引用可以打开正确原文片段；
7. 用户能够继续追问；
8. 用户能够基于回答生成三道练习；
9. 系统能够检查答案、解释错因并保存本轮结果；
10. 用户刷新页面后能够恢复会话、来源和学习产物。

### 19.2 资料不足验收

1. 检索结果不足时不生成确定性课程结论；
2. UI 明确说明资料不足；
3. 用户可以选择扩大章节范围；
4. 用户可以上传临时资料；
5. 在允许公开检索时，回答明确区分课程资料和公开资料。

### 19.3 工具失败验收

1. 工具超时后界面不丢失已生成内容；
2. 用户可以看到失败的是哪个用户动作，而不是内部函数；
3. 用户可以重试、跳过或更换资料范围；
4. 重试不会重复创建多个相同产物或学习记录。

### 19.4 权限验收

1. 学生无法删除课程公共资料；
2. 学生无法修改资料权威等级；
3. 未授权用户无法访问其他课程资料和会话；
4. 前端源码和网络请求中不出现服务端密钥。

### 19.5 响应式验收

1. 桌面端三栏布局可用；
2. 平板端可收起左栏；
3. 移动端来源面板可以打开、关闭并返回原回答位置；
4. 软键盘弹出时输入框仍然可见；
5. 长回答、表格、公式和引用不会横向破坏页面。

## 二十一、最终决策摘要

1. MVP 的一级对象是课程，不是模型、工具或孤立聊天；
2. MVP 必须完成“讲解—引用—练习—反馈—保存”的学习闭环；
3. 正式桌面端采用左侧课程与会话、中央对话、右侧来源/产物/进度的三栏结构；
4. 用户看到的是 Agent 的可验证行动摘要，而不是内部思维链或函数 JSON；
5. 引用和原文定位属于 MVP 核心能力，不是装饰功能；
6. 学习进度只依据练习、理解检查和明确反馈更新；
7. Open WebUI 用于快速联调与内部演示，自研课程工作台用于正式 MVP；
8. 现有 `project_id`、`session_id`、`role`、Evidence、检索、生成、案例分析和引用校验能力可以继续复用；
9. 后端需要补充课程、产物、练习、学习记录和语义 Agent 事件；
10. 待本方案评审通过后，再进入详细前端原型和实施计划。
